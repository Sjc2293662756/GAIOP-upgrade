## 二、数据库设计

### 2.1 连接配置

```javascript
// database/connection.js
const Database = require('better-sqlite3');
let db = null;

function getDb() {
  if (db) return db;
  db = new Database(config.dbPath, {});
  db.pragma('journal_mode = WAL');     // 写入不阻塞读取
  db.pragma('foreign_keys = ON');      // 启用外键约束
  return db;
}
```

- **WAL 模式**：读取和写入可并发，适合升级服务「读状态 + 写日志」场景
- **外键**：`backups.task_id → upgrade_tasks.id`（ON DELETE SET NULL）
- **同步 API**：`better-sqlite3` 使用同步 API，代码简洁，无需 async/await

### 2.2 完整 DDL

```sql
-- 组件当前状态表
CREATE TABLE IF NOT EXISTS components (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT    UNIQUE NOT NULL,
    type        TEXT    NOT NULL CHECK(type IN ('openclaw', 'frontend', 'skill')),
    version     TEXT    NOT NULL,
    status      TEXT    DEFAULT 'active' CHECK(status IN ('active', 'upgrading', 'degraded')),
    install_path TEXT   NOT NULL,
    updated_at  TEXT    DEFAULT (datetime('now'))
);

-- 升级任务表
CREATE TABLE IF NOT EXISTS upgrade_tasks (
    id          TEXT    PRIMARY KEY,
    type        TEXT    NOT NULL CHECK(type IN ('skill-single', 'skill-bundle', 'openclaw', 'frontend', 'full-stack', 'rollback')),
    component   TEXT    NOT NULL,
    old_version TEXT,
    new_version TEXT,
    status      TEXT    DEFAULT 'pending' CHECK(status IN ('pending', 'running', 'success', 'failed', 'rolling_back', 'rolled_back')),
    steps       TEXT    DEFAULT '[]',       -- JSON: [{step, status, message, started_at, finished_at}]
    started_at  TEXT,
    finished_at TEXT,
    operator    TEXT,
    error       TEXT,
    created_at  TEXT    DEFAULT (datetime('now'))
);

-- 备份记录表
CREATE TABLE IF NOT EXISTS backups (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    component   TEXT    NOT NULL,
    version     TEXT    NOT NULL,
    backup_path TEXT    NOT NULL,
    size_bytes  INTEGER DEFAULT 0,
    task_id     TEXT,
    created_at  TEXT    DEFAULT (datetime('now')),
    FOREIGN KEY (task_id) REFERENCES upgrade_tasks(id) ON DELETE SET NULL
);

-- 审计日志表
CREATE TABLE IF NOT EXISTS audit_log (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    action      TEXT    NOT NULL,
    component   TEXT,
    task_id     TEXT,
    operator    TEXT,
    ip          TEXT,
    detail      TEXT    DEFAULT '{}',   -- JSON
    created_at  TEXT    DEFAULT (datetime('now'))
);

-- Schema 版本表
CREATE TABLE IF NOT EXISTS schema_version (
    version     INTEGER PRIMARY KEY,
    applied_at  TEXT    DEFAULT (datetime('now'))
);

-- 索引
CREATE INDEX IF NOT EXISTS idx_tasks_status     ON upgrade_tasks(status);
CREATE INDEX IF NOT EXISTS idx_tasks_component  ON upgrade_tasks(component);
CREATE INDEX IF NOT EXISTS idx_tasks_created    ON upgrade_tasks(created_at DESC);
CREATE INDEX IF NOT EXISTS idx_backups_component ON backups(component);
CREATE INDEX IF NOT EXISTS idx_backups_created  ON backups(created_at DESC);
CREATE INDEX IF NOT EXISTS idx_audit_action     ON audit_log(action);
CREATE INDEX IF NOT EXISTS idx_audit_created    ON audit_log(created_at DESC);
```

### 2.3 审计日志操作类型

| `action` | 触发场景 |
|---|---|
| `validate_pass` / `validate_fail` | 升级包校验 |
| `upgrade_start` | 开始执行升级 |
| `upgrade_success` / `upgrade_failed` | 升级完成/失败 |
| `auto_rollback_start` / `auto_rollback_success` / `auto_rollback_failed` | 自动回滚 |
| `rollback_request` / `rollback_success` / `rollback_failed` | 手动回滚 |
| `backup_cleanup` | 定时清理备份 |

## 三、升级包规范

### 3.1 包格式

统一 ZIP 格式，命名规范：`<component>-<version>.zip`

### 3.2 包内结构

```
<package>.zip
├── upgrade-manifest.json    ← 必填：元信息 + 校验数据
└── skills/ 或 dist/ 或 ...  ← 实际组件文件
```

### 3.3 upgrade-manifest.json 规范

```json
{
  "type": "skill-single",
  "component": "napm-diag",
  "version": "2.1.0",
  "display_name": "NAPM 网络诊断 Skill",
  "description": "功能描述...",
  "changelog": "v2.1.0:\n- 新增: ...\n- 修复: ...",

  "compatibility": {
    "min_openclaw_version": "2026.5.0",
    "min_frontend_version": "2.0.0",
    "napm_api_version": "v2"
  },

  "dependencies": {
    "skills": {
      "napm-alert": ">=1.2.0, <2.0.0"
    }
  },

  "pre_upgrade_actions": [],
  "post_upgrade_actions": ["reload_skill"],

  "signature": {
    "algorithm": "RSA-SHA256",
    "value": "<base64-encoded-signature>",
    "signed_by": "NAPM Skill Team",
    "signed_at": "2026-07-16T10:00:00Z"
  },

  "files_checksum": {
    "algorithm": "sha256",
    "entries": {
      "skills/napm-diag/SKILL.md": "e3b0c44298fc1c149afbf4c8996fb924...",
      "skills/napm-diag/scripts/run_diag.js": "a7ffc6f8bf1ed76651c14756a..."
    }
  }
}
```

### 3.4 必填字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | String | `skill-single` / `skill-bundle` / `openclaw` / `frontend` / `full-stack` |
| `component` | String | 组件标识；`skill-single` 必填，`full-stack` 可省略 |
| `version` | String | SemVer 2.0 格式 |
| `compatibility` | Object | 兼容性要求（至少包含一个检查项） |
| `signature` | Object | `{ algorithm, value }` |
| `files_checksum` | Object | `{ algorithm, entries }` |

### 3.5 签名机制

**RSA-SHA256 over Canonical Digest**：

```
签名流程（CI/打包脚本）:
  1. 收集要打包的文件列表
  2. 按字典序排列文件路径
  3. 计算每个文件的 SHA256 → 填入 files_checksum.entries
  4. 构造规范化摘要: "{path1}:{sha256_1}\n{path2}:{sha256_2}\n..."
  5. 用 RSA 私钥签名摘要 → 填入 signature.value
  6. 打包为 ZIP

校验流程（升级服务）:
  1. 解压 ZIP，读取 manifest
  2. 逐文件计算 SHA256，与 manifest 比对
  3. 重建规范化摘要（同上）
  4. 用公钥验证 signature.value
  5. 签名 + 哈希 均通过 → 合法
```

**密钥管理**：
- 私钥：存储在 CI/CD 环境（加密），用于签名
- 公钥：部署在服务器 `config/public.pem`，用于验证
- 轮转策略：默认每 12 个月；支持多公钥并行过渡

## 四、原子替换模式

所有 Upgrader 统一使用原子替换：

```bash
# 1. 将新文件写入临时目录
cp -a <source> <target>.new

# 2. 原子 mv（同文件系统 rename = 原子操作）
mv <target>.new <target>

# 3. 旧版本保留到 <target>.old（可用于紧急恢复）
#    确认冒烟通过后再清理
```

**优势**：
- 不被中途读取到半完成状态
- 失败时不破坏原有文件（`.new` 可安全删除）
- `rename` 系统调用保证原子性

## 五、版本比较与兼容性处理

### 5.1 SemVer 约束表达式

使用 `semver` 库（^7.6.3），支持：

| 表达式 | 含义 |
|---|---|
| `>=1.2.0` | 至少 1.2.0 |
| `>=1.2.0, <2.0.0` | 1.x 系列 |
| `~1.2.3` | >=1.2.3 且 <1.3.0 |
| `^1.2.3` | >=1.2.3 且 <2.0.0 |

### 5.2 约束规范化

manifest 中的逗号分隔约束（`>=1.2.0, <2.0.0`）自动转换为空格分隔（`>=1.2.0 <2.0.0`），因为 `semver` 库不支持逗号分隔的 AND。

### 5.3 非标准版本处理

OpenClaw 使用日历版本（如 `2026.5.4`），通过 `semver.coerce()` 转换为标准 SemVer 进行比较：

```javascript
semver.coerce('2026.5.4')  // → '2026.5.4' (as semver)
semver.gte(coerced, required)
```

## 六、并发锁模型

```
锁粒度                                  锁文件路径
skill-single  → UPGRADE_LOCK:<name>    /tmp/UPGRADE_LOCK:<name>.lock
skill-bundle  → UPGRADE_LOCK:skills    /tmp/UPGRADE_LOCK:skills.lock
openclaw      → UPGRADE_LOCK:openclaw  /tmp/UPGRADE_LOCK:openclaw.lock
frontend      → UPGRADE_LOCK:frontend  /tmp/UPGRADE_LOCK:frontend.lock
full-stack    → UPGRADE_LOCK:full-stack /tmp/UPGRADE_LOCK:full-stack.lock
```

**参数配置**：
- `retries: 0` — 不重试，获取失败立即返回
- `stale: 300000` — 5 分钟过期（防进程崩溃死锁）
- Windows 降级：`proper-lockfile` 不可用时自动跳过（返回 no-op release）
