# GAIOP 升级数据留存第一批实现基线

| 属性 | 内容 |
|---|---|
| 日期 | 2026-08-09 |
| 范围 | 升级包、上传 staging、组件回滚备份 |
| 策略版本 | `gaiop_upgrade_retention.v1` |
| 自动删除 | 生产默认关闭 |

## 1. 所有权与目录

- 升级服务只管理当前配置的升级数据库同级 `packages`、`NAPM_UPGRADE_PACKAGE_STAGING_ROOT` 和 `NAPM_UPGRADE_BACKUP_ROOT`。
- 只识别严格 UUID v4 `.zip`；未知文件、未知目录、无数据库归属包和符号链接只记录、不删除。
- 不处理 Admin、报告、会话、告警、数据源、操作系统日志、`upgrade.db` 内容或任何 `.bak`。

## 2. 包规则

- `success` 包仍在任务完成后立即删除；失败时由 timer 补偿。
- `failed`、`rolled_back` 包保留至少 7 天，任务时间与文件物理时间均到期才删除。
- `pending`、`running`、`rolling_back` 包不删除。
- staging 中严格 UUID v4 `.zip` 的物理修改时间超过 24 小时才删除。

## 3. 备份规则

- 自动删除必须同时满足超过 90 天和超出每组件最近 5 个可用物理备份组。
- 可用组必须位于配置根内、实际存在、非空、非符号链接且真实路径仍位于根内。
- 多条数据库记录共享物理目录时按一个组计算；任一引用未到期、受保护或不安全时整组不删除。
- 先删除物理目录；成功后才以事务删除全部共享数据库记录。物理失败、目录缺失或路径异常保留数据库记录并写一致性摘要。
- 存在 `running` 或 `rolling_back` 任务时，整批跳过备份清理。
- 人工备份删除复用相同的根目录、真实路径、符号链接和共享引用安全实现，但不套用自动期限。

## 4. 调度、开关和审计

- one-shot：`src/retention-cleanup.js`。
- timer：`gaiop-upgrade-retention-cleanup.timer`，每日 UTC 执行一次。
- 旧 `BackupCleaner.start()` 进程内 cron 已移除，避免双重调度。
- `GAIOP_UPGRADE_RETENTION_AUTO_DELETE=false` 是生产默认值；首次开启前必须只读列出候选并获得单独确认。
- 每类每批默认最多处理 100 个，按最老优先；重复执行幂等。
- 审计只写策略版本、类别、截止时间、成功/跳过/失败数量、释放字节、稳定失败原因和起止时间；审计文件不进入本批清理，按 3 年保护。

## 5. 明确未实施

本批没有实现磁盘水位清理、容量统计、模拟清理、统一策略界面、升级任务记录清理，也没有修改 OpenClaw、频道插件、报告和后端仓库。
