## 二、测试架构

### 2.1 测试辅助工具（test/helpers.js）

提供构建合法签名升级包的工具函数，让每个测试用例可以独立创建所需场景：

| 函数 | 用途 |
|---|---|
| `buildSignedPackage(manifest, files)` | 通用签名包构建器 |
| `buildSkillPackage(overrides)` | 合法 skill-single 包 |
| `buildBundlePackage(overrides)` | 合法 skill-bundle 包 |
| `buildOpenClawPackage(overrides)` | 合法 openclaw 包 |
| `buildFrontendPackage(overrides)` | 合法 frontend 包 |
| `buildFullStackPackage(overrides)` | 合法 full-stack 包 |
| `buildTamperedPackage(overrides)` | 签名被篡改的包 |
| `buildChecksumMismatchPackage(overrides)` | 哈希不匹配的包 |
| `buildNoManifestPackage()` | 无 manifest 的包 |

**签名机制**：测试使用 `config/private.pem`（RSA 私钥，gitignored）签名，`config/public.pem`（公钥）验证。密钥对仅在本地使用。

### 2.2 依赖注入设计

所有 Upgrader 和 Engine 支持 `{ db, config }` 构造参数，测试可传入临时目录：

```javascript
// 测试中的临时数据库
const db = new Database(':memory:');  // 或临时文件路径
initSchema(db);  // 手动建表
seedComponents(db);  // 手动播种

// 将 db 注入到被测对象
const validator = new UpgradeValidator({ publicKey, db });
```

测试结束后：
- `:memory:` 数据库自动销毁
- 临时文件目录通过 `fs.rmSync(tmpDir, { recursive: true, force: true })` 清理

**关键测试用例示例**：

```javascript
// 签名验证 — 合法签名应通过
test('合法签名的包应通过', async (t) => {
  const pkg = buildSkillPackage();
  const result = validator.validate(pkg);
  assert.strictEqual(result.valid, true);
});

// 签名验证 — 篡改应拒绝
test('签名被篡改的包应拒绝', async (t) => {
  const pkg = buildTamperedPackage();
  const result = validator.validate(pkg);
  assert.strictEqual(result.valid, false);
  assert.ok(result.errors.some((e) => e.field === 'signature'));
});

// 版本方向 — 降级应拒绝
test('新版本低于当前版本应拒绝', async (t) => {
  const pkg = buildSkillPackage({ version: '1.0.0' });
  const result = validator.validate(pkg);
  assert.strictEqual(result.valid, false);
  assert.ok(result.errors.some((e) => e.field === 'version'));
});
```

```

失败路径(early): pending → running → failed  (backup之前)

回滚失败:       pending → running → rolling_back → failed + degraded
```

## 四、测试编写规范

### 4.1 新加测试模式

```javascript
const { test } = require('node:test');
const assert = require('node:assert/strict');

test('功能描述', async (t) => {
  // 1. Arrange — 准备测试数据
  // 2. Act — 执行被测操作
  // 3. Assert — 验证结果
  assert.strictEqual(actual, expected);
});
```

### 4.2 子测试分组

```javascript
test('UpgradeValidator', async (t) => {
  await t.test('签名验证', async (t) => {
    await t.test('合法签名应通过', async () => { /* ... */ });
    await t.test('篡改签名应拒绝', async () => { /* ... */ });
  });

  await t.test('兼容性检查', async (t) => {
    await t.test('全部通过', async () => { /* ... */ });
    await t.test('OpenClaw不满足', async () => { /* ... */ });
  });
});
```

### 4.3 测试数据隔离

- 使用 `test/helpers.js` 中的构建函数创建独立测试包
- 每个测试用例独立的临时目录和内存数据库
- 测试结束后 `fs.rmSync` 清理
