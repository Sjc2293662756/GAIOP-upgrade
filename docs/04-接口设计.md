# 接口设计

> **历史接口提示（2026-07-30）：** 浏览器不直连本服务，Caddy认证头不是当前生产授权来源；除 `/health` 外的接口必须由Admin BFF携带内部Token和操作者身份。当前边界见[237生产适配基线](2026-07-30-GAIOP升级模块237生产适配基线.md)。

> 版本：v1.0 | 日期：2026-07-17 | 基础路径：`/api/v1/upgrade`

---

## 一、接口总览

```
服务端口: localhost:18900 (仅通过 Caddy :443 反向代理暴露)

GET    /health                    健康检查（无需认证）
GET    /api/v1/upgrade/status     组件清单 + 维护模式状态
POST   /api/v1/upgrade/validate   上传 ZIP → 全校验 → 创建 pending 任务
POST   /api/v1/upgrade/execute    执行 pending 任务
GET    /api/v1/upgrade/tasks      任务列表（支持筛选分页）
GET    /api/v1/upgrade/tasks/:id  任务详情 + 步骤进度
POST   /api/v1/upgrade/rollback   手动回滚
GET    /api/v1/upgrade/backups    备份列表
```

---

## 二、认证模型

```
用户请求
    │
    ▼
Caddy (:443)
    │ Basic Auth 验证
    ├── 未通过 → 401 Unauthorized
    │
    ▼ 通过
Caddy 添加 X-Authenticated-User: <username> 头
    │
    ▼
升级服务 (:18900)
    │ 从 req.headers['x-authenticated-user'] 提取
    │ 挂载到 req.operator
    │ 写入 audit_log.operator
    ▼
业务处理
```

> 升级服务信任 Caddy 传递的认证头，自身不做二次认证。

## 三、通用约定

### 3.1 错误响应格式

所有错误统一返回：

```json
{
  "error": true,
  "message": "人类可读的错误描述"
}
```

### 3.2 HTTP 状态码

| 状态码 | 含义 |
|---|---|
| 200 | 请求成功（同步响应） |
| 202 | 已接受（异步任务已提交） |
| 400 | 请求参数错误 |
| 404 | 资源不存在 |
| 409 | 状态冲突（如任务状态不对） |
| 422 | 校验失败 |
| 423 | 资源锁定（并发冲突） |
| 500 | 服务器内部错误 |

### 3.3 字段命名

- JSON 字段统一使用 `snake_case`：`task_id`, `new_version`, `backup_path`
- 查询参数使用 `snake_case`：`?target_version=2.0.1`

### 4.3 POST /api/v1/upgrade/validate — 上传校验

接收升级包 ZIP 文件，执行完整校验链但不执行升级。

**请求**：`Content-Type: multipart/form-data`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | File (.zip) | **是** | 升级包文件 |
| `force` | Boolean | 否 | 跳过非关键警告（默认 false） |

**响应 200**（校验通过）：

```json
{
  "task_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "valid": true,
  "type": "skill-single",
  "component": "napm-diag",
  "current_version": "2.0.1",
  "new_version": "2.1.0",
  "display_name": "NAPM 网络诊断 Skill",
  "changelog": "v2.1.0:\n- 新增: 支持 IPv6 流量分析\n- 修复: 大时间范围查询超时问题",
  "compatibility_check": {
    "openclaw": {
      "current": "2026.5.4",
      "required": ">=2026.5.0",
      "ok": true
    },
    "frontend": {
      "current": "2.0.0",
      "required": ">=2.0.0",
      "ok": true
    },
    "napm_api": {
      "current": "v2",
      "required": "v2",
      "ok": true
    },
    "dependencies": {
      "napm-alert": {
        "current": "1.2.0",
        "required": ">=1.2.0, <2.0.0",
        "ok": true
      }
    }
  },
  "impact": {
    "requires_restart": false,
    "requires_maintenance": false,
    "affected_components": ["napm-diag"],
    "estimated_downtime_seconds": 0
  },
  "warnings": []
}
```

**响应 422**（校验失败）：

```json
{
  "task_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "valid": false,
  "errors": [
    {
      "field": "version",
      "message": "新版本 2.0.0 不高于当前版本 2.0.1"
    },
    {
      "field": "compatibility.openclaw",
      "message": "当前 OpenClaw 2026.4.0 不满足最低要求 2026.5.0，请先升级 OpenClaw"
    },
    {
      "field": "signature",
      "message": "签名验证失败：签名不匹配，包可能被篡改"
    },
    {
      "field": "files_checksum",
      "message": "文件 skills/napm-diag/main.py 的 SHA256 不匹配"
    }
  ]
}
```

**校验链（7 阶段）**：

```
阶段 1: ZIP 解压 → 读取 upgrade-manifest.json
阶段 2: manifest 必填字段校验
阶段 3: SHA256 逐文件校验
阶段 4: RSA-SHA256 签名验证
阶段 5: 版本方向检查（新 > 当前）
阶段 6: 兼容性检查（OpenClaw/前端/API + Skills 依赖）
阶段 7: 影响范围评估
```

> 校验通过后，系统自动创建 `pending` 状态的任务并保存 ZIP 文件到 `packages/` 目录，供后续 `execute` 使用。

---

### 4.4 POST /api/v1/upgrade/execute — 执行升级

对已通过校验的 pending 任务执行升级。

**请求**：`Content-Type: application/json`

```json
{
  "task_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "force": false
}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `task_id` | String | **是** | 校验时返回的任务 ID |
| `force` | Boolean | 否 | 强制执行（跳过非关键警告） |

**响应 202**：

```json
{
  "task_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "status": "accepted",
  "tracking_url": "/api/v1/upgrade/tasks/a1b2c3d4-e5f6-7890-abcd-ef1234567890"
}
```

**错误响应**：

| 状态码 | 场景 |
|---|---|
| 400 | 缺少 `task_id` 或 ZIP 文件丢失 |
| 404 | 任务不存在 |
| 409 | 任务状态不是 `pending`（已执行或已完成） |
| 423 | 存在并发升级任务 |

---

### 4.5 GET /api/v1/upgrade/tasks — 任务列表

| `failed` / `rolling_back` | 已完成的步骤比例 |

### 4.7 POST /api/v1/upgrade/rollback — 手动回滚

将指定组件回滚到历史备份版本。

**请求**：`Content-Type: application/json`

```json
{
  "component": "napm-diag",
  "target_version": "2.0.1"
}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `component` | String | **是** | 组件名 |
| `target_version` | String | 否 | 目标版本；为空时回滚到上一版本 |
| `task_id` | String | 否 | 关联的原始升级任务 ID |

**响应 202**：

```json
{
  "component": "napm-diag",
  "target_version": "2.0.1",
  "status": "accepted",
  "message": "正在回滚 napm-diag 到版本 2.0.1"
}
```

**错误响应**：

| 状态码 | 场景 |
|---|---|
| 400 | 缺少 `component` 或找不到历史版本 |
| 404 | 指定版本的备份不存在 |
| 423 | 存在并发操作锁定 |

## 五、影响范围评估参考

| 升级类型 | 需重启 | 需维护模式 | 预估停机 |
|---|---|---|---|
| `skill-single` | ❌ | ❌ | 0 秒 |
| `skill-bundle` | ❌ | ❌ | 0 秒 |
| `openclaw` | ✅ | ✅ | ~30 秒 |
| `frontend` | ❌ | ❌ | 0 秒 |
| `full-stack` | ✅ | ✅ | ~60 秒 |

## 六、前端轮询建议

管理前端可通过轮询以下端点获取实时状态：

| 用途 | 端点 | 建议频率 |
|---|---|---|
| 组件健康状态 | `GET /status` | 每 10s |
| 任务进度追踪 | `GET /tasks/:id` | 每 1s（执行中）/ 停止（完成） |
| 维护模式检测 | `GET /status` → `maintenance_mode` | 每 5s |
