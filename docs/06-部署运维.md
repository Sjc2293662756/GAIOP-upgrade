## 二、首次部署

### 2.1 服务器准备

```bash
# 1. SSH 登录远端服务器
ssh netinside@101.254.114.237

# 2. 确认 Node.js 和 npm 版本
node -v   # v22.14.0
npm -v    # v10.9.2

# 3. 创建目录结构
sudo mkdir -p /opt/napm-upgrade/{src,config,data,packages}
sudo mkdir -p /var/backups/napm/{skills,openclaw,frontend}
sudo mkdir -p /var/www/napm-admin

# 4. 设置权限
sudo chown -R netinside:netinside /opt/napm-upgrade
sudo chown -R netinside:netinside /var/backups/napm
sudo chown -R netinside:netinside /var/www/napm-admin
```

### 2.2 部署升级服务

```bash
# 1. 克隆仓库
cd /opt
git clone https://github.com/Sjc2293662756/GAIOP-upgrade.git napm-upgrade
cd napm-upgrade

# 2. 安装依赖（产品模式）
npm ci --production

# 3. 配置环境变量
cp .env.example .env
vim .env   # 按需修改路径和端口

# 4. 复制 RSA 公钥到配置目录
cp config/public.pem /opt/napm-upgrade/config/

# 5. 初始化数据库
npm run db:init

# 6. 测试启动
npm start
# 另开终端验证: curl http://localhost:18900/health
```

### 2.3 安装 systemd 服务

```bash
# 1. 创建服务文件
sudo tee /etc/systemd/system/napm-upgrade.service << 'EOF'
[Unit]
Description=NAPM Upgrade Orchestration Service
After=network-online.target openclaw.service
Wants=network-online.target

[Service]
Type=simple
User=netinside
Group=netinside
WorkingDirectory=/opt/napm-upgrade
ExecStart=/usr/local/bin/node /opt/napm-upgrade/src/index.js
ExecReload=/bin/kill -HUP $MAINPID
Restart=always
RestartSec=10
StandardOutput=journal
StandardError=journal
SyslogIdentifier=napm-upgrade

# 安全加固
NoNewPrivileges=yes
PrivateTmp=yes
ProtectSystem=strict
ProtectHome=read-only
ReadWritePaths=/opt/napm-upgrade /var/backups/napm /home/netinside/.openclaw /home/netinside/.npm-global/lib/node_modules/openclaw /var/www/napm-admin
ReadOnlyPaths=/etc/caddy/Caddyfile
CapabilityBoundingSet=

[Install]
WantedBy=multi-user.target
EOF

# 2. 启用并启动
sudo systemctl daemon-reload
sudo systemctl enable napm-upgrade
sudo systemctl start napm-upgrade

# 3. 验证
sudo systemctl status napm-upgrade
curl http://localhost:18900/health
```

### 2.4 配置 Caddy 反向代理

编辑 `/etc/caddy/Caddyfile`，在现有配置中添加升级服务路由：

```caddy
# 升级服务 API（追加到 Caddyfile）
handle_path /api/upgrade/* {
    reverse_proxy localhost:18900
}

# 管理前端静态文件（Phase 5 部署后启用）
handle_path /napm-admin/* {
    root * /var/www/napm-admin
    file_server
}

# SPA fallback（前端路由）
@napm_admin_spa {
    path /napm-admin/*
    not file
}
handle @napm_admin_spa {
    root * /var/www/napm-admin
    rewrite * /napm-admin/index.html
}
```

重载 Caddy 配置：

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

### 2.5 验证部署

```bash
# 通过 Caddy 访问（需 Basic Auth）
curl -u netinside:your_password https://101.254.114.237/api/upgrade/status

# 直接本地验证
curl http://localhost:18900/health
curl http://localhost:18900/api/v1/upgrade/status
```

## 四、日常运维

### 4.1 常用命令

```bash
# 查看升级服务状态
sudo systemctl status napm-upgrade

# 查看升级服务日志
sudo journalctl -u napm-upgrade -f
sudo journalctl -u napm-upgrade -n 100

# 重启升级服务
sudo systemctl restart napm-upgrade

# 查看端口占用
ss -tlnp | grep -E '18789|18900|443'

# 查看备份目录大小
du -sh /var/backups/napm/*/

# 查看磁盘剩余空间
df -h /
```

### 4.2 查询数据库

```bash
# 查看组件当前版本
sqlite3 /opt/napm-upgrade/data/napm-upgrade.db \
  "SELECT name, type, version, status FROM components;"

# 查看最近 10 次升级记录
sqlite3 /opt/napm-upgrade/data/napm-upgrade.db \
  "SELECT id, component, old_version, new_version, status, created_at
   FROM upgrade_tasks ORDER BY created_at DESC LIMIT 10;"

# 查看审计日志
sqlite3 /opt/napm-upgrade/data/napm-upgrade.db \
  "SELECT action, component, operator, created_at
   FROM audit_log ORDER BY created_at DESC LIMIT 20;"

# 查看备份占用
sqlite3 /opt/napm-upgrade/data/napm-upgrade.db \
  "SELECT component, COUNT(*) as cnt, SUM(size_bytes) as total_bytes
   FROM backups GROUP BY component;"
```

### 4.3 检查清单

| 操作 | 频率 | 方式 |
|---|---|---|
| 检查组件健康状态 | 每日 | `GET /api/v1/upgrade/status` |
| 检查磁盘空间 | 每周 | `df -h /` |
| 检查备份目录大小 | 每周 | `du -sh /var/backups/napm/` |
| 检查系统日志异常 | 每周 | `journalctl -u napm-upgrade --since "1 week ago" \| grep -i error` |
| 清理旧备份 | 自动 | node-cron 每天 02:00 |

## 五、升级操作 SOP

```
1. 准备阶段
   ├─ 确认升级包已通过 CI 签名
   ├─ 通知相关用户（如涉及 OpenClaw 重启）
   └─ 在低峰时段执行（OpenClaw 升级推荐凌晨）

2. 上传校验
   ├─ 通过 API 或管理前端上传 ZIP
   ├─ 检查校验结果（兼容性 + 影响范围）
   └─ 如有 warning，评估是否需要 --force

3. 执行升级
   ├─ POST /api/v1/upgrade/execute { task_id }
   ├─ 轮询 GET /api/v1/upgrade/tasks/:id 跟踪进度
   └─ 如有失败，系统自动回滚

4. 升级后验证
   ├─ 确认 GET /status 中版本已更新
   ├─ 手动测试受影响功能
   └─ 观察 5–10 分钟确认无异常

5. 异常处理
   ├─ 自动回滚失败 → 查看 journalctl 日志
   ├─ 必要时手工恢复: cp -a /var/backups/napm/<comp>/<backup> → 目标路径
   └─ 标记 degraded 的组件需要排查后手动恢复
```

## 六、应急恢复

### 6.1 升级服务自身故障

```bash
# 1. 查看状态
sudo systemctl status napm-upgrade

# 2. 查看最近的错误日志
sudo journalctl -u napm-upgrade -n 100 --no-pager

# 3. 重启
sudo systemctl restart napm-upgrade

# 4. 如果 SQLite 数据库损坏（极少见）
cp /opt/napm-upgrade/data/napm-upgrade.db \
   /opt/napm-upgrade/data/napm-upgrade.db.bak.$(date +%Y%m%d)
# 重新初始化（会丢失历史记录，但不影响线上组件）
sudo systemctl restart napm-upgrade
```

### 6.2 手工回滚（升级服务不可用时）

```bash
# === Skill 回滚 ===
cd /home/netinside/.openclaw/workspace/skills/
mv napm-diag napm-diag.broken
cp -a /var/backups/napm/skills/napm-diag_2.0.1_20260715 napm-diag
touch napm-diag/SKILL.md
# 等待 3 秒让热加载生效

# === OpenClaw 回滚 ===
cd /home/netinside/.npm-global/lib/node_modules/
mv openclaw openclaw.broken
cp -a /var/backups/napm/openclaw/openclaw_2026.5.4_20260715 openclaw
sudo systemctl restart openclaw
# 等待健康检查通过: curl http://localhost:18789/health
```

### 6.3 OpenClaw systemd 服务

```ini
# /etc/systemd/system/openclaw.service

ExecReload=/bin/kill -HUP $MAINPID
```

## 八、监控指标

### 8.1 关键指标

| 指标 | 含义 | 告警阈值 |
|---|---|---|
| 升级成功率 | `success / (success + failed)` | < 90% |
| 回滚率 | 自动回滚次数 / 升级次数 | > 20% |
| 校验失败率 | 签名/哈希校验失败次数 | > 0（安全事件） |
| 磁盘可用空间 | `df -h /` | < 2 GB |
| 服务可用性 | `GET /health` 返回 200 | 非 200 |
