## 1. 正式链路

```text
浏览器
→ GAIOP Admin BFF（管理员认证、确认口令、审计、响应脱敏）
→ 内部 Token + 当前管理员身份
→ 127.0.0.1:18900 gaiop-upgrade.service
→ 签名、清单、版本和 ZIP 安全校验
→ 备份 → 组件替换 → 固定重载/健康检查
→ 成功清理上传包；失败自动回滚
```

浏览器不知道升级服务地址、内部Token、安装路径和备份路径。升级控制信息不通过Gateway或模型传输。18900只监听回环地址，不作为公网入口。

代码中仍保留部分 `NAPM_UPGRADE_*` 环境变量名作为内部兼容接口；判断运行目录必须看部署环境中的实际值，不得因变量名前缀回退到旧NAPM路径。新增生产鉴权和监听配置使用 `GAIOP_UPGRADE_INTERNAL_TOKEN`、`GAIOP_UPGRADE_HOST`。

## 3. 认证和权限

- 生产环境缺少 `GAIOP_UPGRADE_INTERNAL_TOKEN` 时服务拒绝启动。
- `/health` 仅用于本机存活检查；其他接口缺少或使用错误Token时返回401。
- 非健康接口还必须携带BFF注入的当前管理员身份。
- Admin BFF负责管理员权限、确认口令和页面审计；升级服务保留独立执行审计。
- 升级服务以root运行以原子管理 `gaiop` 和 `netinside` 两套所有者目录，但受回环监听、内部Token、签名/ZIP校验、固定目标路径和systemd沙箱共同限制。
- OpenClaw重启只能调用固定辅助程序 `/usr/local/libexec/gaiop-upgrade-restart-openclaw`，不能传入任意服务名或命令。

## 4. 升级包与执行能力

当前清单类型：

| 类型 | 用途 |
|---|---|
| `skill-single` | 单个Skill |
| `skill-bundle` | Skills集合 |
| `openclaw` | OpenClaw核心 |
| `frontend` | Admin前端 `dist` |
| `full-stack` | OpenClaw、Skills和前端组合 |

所有ZIP必须通过签名、清单、文件校验和、组件名、允许目录、重复条目和路径穿越检查。Admin前端目标最后一级必须是 `dist`，不得把包含BFF、运行数据或配置的 `/opt/gaiop/admin` 整体替换。

任务只有最终状态为 `success` 时才即时清理上传包；即时删除失败由独立留存 timer 补偿。`failed`、`rolled_back` 等明确终态任务的严格 UUID 包保留 7 天，活动任务包不参与清理；无数据库归属的包只记录、不删除。替换前创建受控备份，健康检查失败时按组件或全栈事务自动恢复。

2026-08-09 起，旧的进程内备份 cron 已移除。独立 `gaiop-upgrade-retention-cleanup.timer` 每日调用 one-shot；生产自动删除总开关默认关闭。组件回滚备份只有同时超过 90 天且超出每组件最近 5 个经过路径、实体和可用性验证的物理备份组时才可删除；共享目录必须全部引用满足条件，物理删除成功后才删除数据库记录。详细边界见[升级数据留存第一批实现基线](2026-08-09-GAIOP升级数据留存第一批实现基线.md)。

## 6. 尚未扩展为已验收能力

当前已经完成“服务部署、页面/BFF接入、安全校验和部署级自动回滚”，但以下事项仍不能表述为已完成：

- 使用真实业务包执行OpenClaw核心升级；
- 执行真实频道插件升级；
- 完成Gateway/频道插件兼容矩阵；
- 升级后逐一验证全部插件加载和全部已启用频道真实消息；
- 使用真实业务Skill完成完整升级与人工回滚演练；
- 全栈升级后的客户数据、报告、会话和频道综合验收。

OpenClaw核心或频道插件升级属于高风险操作，必须先冻结版本组合、备份完整运行目录和配置，完成全插件/全频道验证，并在任一失败时整体回滚。
