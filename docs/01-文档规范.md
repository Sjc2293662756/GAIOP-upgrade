## 二、文档编写规范

### 2.1 文件命名

| 规则 | 示例 |
|---|---|
| 编号文档用 `NN-中文名.md` | `02-总体设计.md` |
| 日期文档用 `YYYY-MM-DD-中文名.md` | `2026-07-16-NAPM升级模块详细设计.md` |
| 文件名不含空格，中文直接连接 | `03-模块设计.md` ✅ / `03-模块 设计.md` ❌ |

### 2.2 标题层級

- `#` 文档标题（每篇一个）
- `##` 一级章节
- `###` 二级章节
- `####` 三级章节（最深不超四级）

### 2.3 Markdown 规则

- 代码块必须指定语言：```` ```javascript ````
- 表格对齐用 `|---|` 左对齐或 `|---:|` 右对齐
- 路径用反引号包裹：`` `/opt/napm-upgrade/` ``
- 外部链接用完整 URL
- 内部链接用相对路径：`[总体设计](02-总体设计.md)`

### 2.4 图表约定

- 架构图/流程图用 ASCII art（纯文本，不依赖外部工具）
- 序列图用 `│` `├` `▼` `►` 等字符
- 状态机用 Mermaid 风格的纯文本描述

## 三、代码注释规范

### 3.1 文件头注释

每个源文件开头用 JSDoc 风格简述职责：

```javascript
/**
 * 升级任务引擎。
 *
 * 职责：
 * 1. 任务状态机（pending → running → success/failed/rolling_back/rolled_back）
 * 2. 步骤追踪（JSON steps 字段，每步独立时间戳 + 消息）
 * 3. 并发控制（proper-lockfile 文件锁，按组件粒度）
 * 4. 通用执行编排（runSteps + 失败自动回滚）
 */
```

### 3.2 函数注释

公开方法必须注释，私有方法可选：

```javascript
/**
 * 校验升级包。返回结构化结果，与设计文档 7.3.1 节对齐。
 *
 * @param {Buffer} zipBuffer   ZIP 文件的二进制内容
 * @param {object} [options]   可选参数
 * @param {boolean} [options.force=false]  跳过非关键警告
 * @returns {object} 校验结果 { valid, task_id, errors?, ... }
 */
```

### 3.3 分隔注释

模块内部使用分隔注释划分功能区：

```javascript
// ── 数据库初始化 ──────────────────────────────────────────────
// ── Express 应用 ──────────────────────────────────────────────
// ════════════════════════════════════════════════════════════
// POST /execute — 执行升级
```

## 五、Git 提交信息规范

| 前缀 | 用途 | 示例 |
|---|---|---|
| `feat:` | 新功能 | `feat: 添加全栈升级引擎` |
| `fix:` | 修复 Bug | `fix: 修复备份清理未删除过期记录` |
| `refactor:` | 重构代码 | `refactor: 提取公共校验逻辑` |
| `docs:` | 文档修改 | `docs: 完善部署运维文档` |
| `test:` | 测试相关 | `test: 补充前端升级冒烟用例` |
| `chore:` | 工程杂项 | `chore: 升级 better-sqlite3 版本` |

## 六、版本号规范

所有组件版本遵循 SemVer 2.0（`MAJOR.MINOR.PATCH`）：

| 变更类型 | 版本号变化 |
|---|---|
| 不兼容的 API 修改 | MAJOR +1, MINOR 和 PATCH 归零 |
| 向下兼容的功能新增 | MINOR +1, PATCH 归零 |
| 向下兼容的问题修正 | PATCH +1 |

OpenClaw 使用日历版本（如 `2026.5.4`），内部通过 `semver.coerce()` 兼容处理。

## 七、文档维护

- **谁写代码谁写文档**：功能代码和对应文档在同一 PR 中提交
- **设计文档单向更新**：`2026-07-16-NAPM升级模块详细设计.md` 是设计阶段的产物，实施后不再更新；变更记录在 `08-历史决策.md` 中
- **API 变更必须同步更新**：`04-接口设计.md`
- **每次部署后更新**：`06-部署运维.md` 中的服务器配置、环境变量等
